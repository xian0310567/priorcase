## A. 팀 도입 차단 요소 — ✅ 완료 (2026-08-12)

A1·A2·A3 을 한 브랜치에서 끝냈다. A4 는 아직 남았다.

### A1. 도메인 해석을 경로에서 git remote 로 — ✅

지금 `DomainForCwd` 는 설정의 **절대 경로**로 판정한다
(`config.go:265`, `paths = ["~/project/priorcase"]`).

팀원마다 체크아웃 경로가 다르므로 **새 사람이 설정 파일을 손으로 고쳐야 한다.**
`npm i -g priorcase` 직후 첫 경험이 그것이 된다.

`git remote get-url origin` → `xian0310567/priorcase` 는 누구 기계에서든 같다.
경로 매칭은 폴백으로 남긴다 (git 이 아닌 디렉토리도 있다).

### A2. `author` — 누가 내린 결정인가 — ✅

frontmatter 10키에 없다 (`frontmatter.go:14-23`). 팀에서는 "이 결정 누가 왜"가
회수의 절반이다. `Extra` 인라인으로 들어가긴 하지만 스키마·검색 대상이 아니다.

`schema: 2` 로 올리고 `author` 를 정식 키로. 판 1 노트는 그대로 읽힌다
(`IsFuture` 가 이미 있다).

### A3. git 공유 시 충돌하는 자리 — ✅

볼트를 사설 git 레포로 공유할 때:

- `_meta/00-결정-색인.md` — **24KB 를 매번 통째로 재생성.** 두 사람이 각자
  `prior capture` 하면 매번 충돌한다.
- `99-<프로젝트>-작업-로그.md` — 여러 사람이 파일 끝에 append → 충돌.

색인을 gitignore 하고 각자 `prior index` 로 만들게 하거나, 결정 노트에서
파생 가능한 형태로 바꾼다. 작업 로그는 날짜별 파일로 쪼개는 방법이 있다.

### A4. 볼트 분리 — 프로젝트가 10개 섞여 있다 (남음)

`~/Documents/Obsidian Vault` 에 `NOI`(220건) 포함 10개 프로젝트가 있다.
통째로 공유하면 전부 노출된다. **프로젝트 폴더 단위 공유 구조**를 정해야 한다.

지금 `priorcase` 가 안 하는 일이다. 설계 결정이 먼저 필요하다.

## B. 스펙이 v2 로 미룬 것

### B1. 다른 호스트 파서 ★

`internal/transcript/` 아래에 `claudecode` 하나뿐이다 (스펙 §363 이 명시).
팀원이 Cursor·Codex CLI·Claude Desktop·Gemini 를 쓰면 **②주입·③자동기록이
아예 안 돈다.** 데몬 엔진은 완성돼 있고 연료만 없다.

회사에서는 도구가 섞이므로 A 다음으로 급하다.

### B2. 임베딩 검색

지금 회수는 파일명·summary·tags 만 본다 (`search.scoreAll` 의
`headHits == 0 → continue`). 유료층 후보였으나 E2E 와 충돌한다는 결정이 있다.

### B3. 데스크탑 앱 — 우선순위 상향 (2026-08-12)

**음성을 담을 그릇으로서가 아니라 그 자체로 값이 있어서 올린다.** 지금 새 사용자는
`prior init --apply` 를 직접 치고, 무엇이 잡히는지 보려면 `prior doctor` 를 친다.
팀 도입의 첫 마찰이 거기다. 앱이 배선·상태·미확인 구간을 맡으면 온보딩이 달라진다.

**CLI + 훅을 대체하지 않는다.** 앱이 그걸 감싼다 — 둘 중 하나를 고르는 것이 아니다.
그리고 `.app` 배포는 **애플 공증을 되살린다**(npm 경로가 없앴던 비용).

### B4. 협업 도구 소스 · 회의 음성 — 순서 뒤

Jira·Slack·Asana 와 회의 음성까지 소스로. **기준은 "그 소스에 결정이 있는가" 이지
"데이터가 있는가" 가 아니다.** 전부 색인으로 가면 예산이 훨씬 큰 회사들의 링이다.
음성은 참가자 동의 문제가 기술보다 먼저 막을 수 있다.

### B5. 화면 녹화 포착 — 보류

데스크탑을 통째로 녹화해 결정을 뽑는 안. 문제의식은 측정된 것이지만 위 단들이
훨씬 값싸다. 중간 단계로 "창 제목·앱 전환만"(픽셀 없이)도 후보다. 상세는 볼트
`priorcase-결정-화면녹화포착-파서먼저-보류-2026-08-12`.

### B6. 자정 작용 (주제 전환 감지)

스펙이 "규칙으로 판정하기 어렵고 오탐이 방해가 된다"며 뺐다. 실사용 데이터를
보고 정하기로 했다 — 지금 그 데이터가 쌓였다.

## C. 품질 부채

### C1. 회수 사각 77%

볼트 406건 중 회수 대상은 93건뿐. 나머지 313건(참고 문서·설계 문서·작업 로그)은
**영원히 안 걸린다.** 팀 공용 참고 문서를 놔둬도 마찬가지다.

**방향이 정해지지 않았다.** 후보:
- 읽기전용 색인 (결정이 아닌 문서도 회수 대상에 넣되 쓰지는 않는다)
- `source` 개념 분리 (결정/참고를 다른 등급으로)
- 그대로 둔다 (결정만 보는 것이 선별의 핵심이라는 입장)

### C2. 미뤄둔 리뷰 지적

**어디에도 기록돼 있지 않다** — 코드에 표시가 없고 볼트에도 없다.
이 문서가 유일한 기록이 된다.

- 체크포인트 무한 증가 (오래된 항목을 안 지운다)
- 원장 쓰기가 어댑터에 산다 (계층 규칙 위반 소지)
- `startupPass` 가 `At` 이 아니라 `Offset != 0` 으로 판정
- 그 밖 3건 (상세 유실 — 리뷰를 다시 돌려야 한다)

### C3. 커버리지 낮은 자리

전체 79.3%. 60% 미만:
`rollup.go` 14.8% · `doctor.go` 11.1% · 각 `command.go`/`*cmd.go` 0%
(cobra 배선은 0%가 자연스럽지만 `rollup`·`doctor` 본체는 실제 구멍이다)

### C4. CLI 진단 문구 국제화

의도적으로 범위 밖에 뒀다 (에이전트가 읽는 표면만 i18n). 외부 사용자가 생기면
필요해진다 — 내부용이면 보류해도 된다.

### C5. ③ 자동 승격 관찰

컷오버 후 실제로 노트를 만든 것이 **1건**이고, 그 1건에 결함이 둘 있었다
(근거 날조·날짜 2일 오차). 둘 다 고쳤지만 **지시문 제약은 완화이지 보장이 아니다.**
`promotions.jsonl` 의 `rec=true` 를 당분간 사람이 읽어야 한다.
