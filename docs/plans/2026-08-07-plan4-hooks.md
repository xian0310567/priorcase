# Plan 4 — Claude Code 훅 어댑터 + `prior init` + 컷오버

> **에이전트 작업자에게:** 태스크 단위로 구현한다. 각 단계는 체크박스(`- [ ]`)다.

**목표:** Claude Code 에서 **주제 전환 시 회수를 강제**하고(MCP 로는 불가능한 유일한 칸),
기존 셸 훅 5개를 priorcase 로 갈아 끼운다. 이걸로 v1 이 닫힌다.

**아키텍처:** `internal/adapter/hook` 은 입력 JSON 을 파싱해 `core`·`daemon` 을 부르고
stdout 으로 컨텍스트를 낸다. **무슨 일이 있어도 exit 0.**

---

## Global Constraints

- **훅은 무슨 일이 있어도 `exit 0`.** 실패가 대화를 막으면 안 된다. 진단은 stderr.
- **stdout 은 에이전트 컨텍스트다.** `user-prompt-submit`·`session-start` 의 stdout 은
  그대로 주입되므로 경고·진단이 한 줄도 섞이면 안 된다 (MCP 의 stdio 와 같은 규율).
- **`prior init` 은 orca 훅을 건드리지 않는다.** 실측으로 `~/.claude/settings.json` 에는
  second-brain 5개와 orca 12개가 공존한다. second-brain 것만 정확히 걷어낸다.
  하나라도 잘못 지우면 사용자의 다른 시스템이 죽는다.
- **`prior init` 은 되돌릴 수 있어야 한다.** `--revert` 가 원상복구한다. 설정 파일은
  수정 전에 백업한다.
- **어댑터 경계**(§4.1): `hook` 은 `cli`·`mcp` 를 import 하지 않는다. `internal/arch` 가 강제한다.
- 훅이 기록 판별을 하지 않는다. 옛 구현은 훅이 LLM 을 불러 추측했다 —
  [[priorcase-결정-기록회수모델-에이전트주도-2026-08-07]] 가 뒤집은 지점이다.

## 훅 입력 규약 (실측)

가동 중인 셸 구현에서 확인한 필드다. 전부 stdin JSON.

| 이벤트 | 쓰는 필드 |
| --- | --- |
| `session-start` | `.cwd` `.source` |
| `user-prompt-submit` | `.cwd` `.prompt` |
| `stop` | `.cwd` `.session_id` `.stop_hook_active` `.transcript_path` |
| `pre-compact` | `.cwd` `.session_id` `.transcript_path` |
| `session-end` | `.cwd` `.session_id` `.transcript_path` |

## 각 훅이 하는 일

| 이벤트 | 하는 일 | 왜 |
| --- | --- | --- |
| `user-prompt-submit` | `prior recall` 결과를 stdout 으로 주입 | **MCP 로 불가능한 유일한 칸.** 이게 이 어댑터의 존재 이유다 |
| `session-start` | 볼트 요약 + 미확인 구간 + 세션 id 안내 | MCP 의 `instructions` 에 해당 |
| `stop` · `pre-compact` · `session-end` | 데몬이 안 돌면 **직접 스캔** | 아래 참조 |

**★ 데몬 없이도 안전망이 돈다.** `prior watch` 는 상태 디렉토리에 flock 을 잡고 산다.
훅이 `TryLock` 을 해서 **얻으면 데몬이 없는 것**이므로 자기가 스캔하고 놓는다. 못 얻으면
데몬이 돌고 있으므로 건너뛴다. 소유자가 언제나 하나뿐이라 중복 처리가 구조적으로 없고,
데몬 등록에 실패한 사용자도 턴 경계마다 안전망을 얻는다.

## `source_session` 을 정리한다

Plan 2 에서 MCP capture 가 `req.Session.ID()` 를 `source_session` 에 넣게 했는데,
**stdio MCP 에는 세션 id 가 없다** — 실측으로 항상 빈 문자열이다. 죽은 배선이다.

- MCP 의 죽은 배선을 걷어낸다.
- `priorcase_capture` / `prior capture` 에 **선택적 `session_id`** 를 받는다.
- `session-start` 훅이 주입 컨텍스트에 세션 id 를 적어 에이전트가 넘길 수 있게 한다.
- 데몬의 중복 대조는 **`source_session` 이 있으면 그걸로, 없으면 날짜+도메인으로** 한다.
  Plan 3 의 날짜 단위 대조를 대체하는 게 아니라 정밀화하는 것이다.

## 이 계획에서 하지 않는 것

- **데몬 자동 등록(launchd/systemd)** — `prior init` 이 **안내만** 한다. 사용자의 시스템에
  서비스를 등록하는 것은 되돌리기 어렵고, 위의 훅 폴백이 있어 필수가 아니다.
- **실제 컷오버 실행** — `prior init` 을 만들되 사용자의 실 설정에 돌리지 않는다.
  그건 사용자가 결정할 일이다 (§12 게이트를 먼저 확인한다).
- 다른 호스트 훅 — v2.
