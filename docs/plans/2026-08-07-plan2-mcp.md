# Plan 2 — MCP 서버 구현 계획

> **에이전트 작업자에게:** 태스크 단위로 구현한다. 각 단계는 체크박스(`- [ ]`)다.

**목표:** `cb mcp` 로 뜨는 MCP stdio 서버를 만들어, MCP 를 말하는 모든 호스트에서
casebook 의 기록·회수를 쓸 수 있게 한다.

**아키텍처:** `internal/adapter/mcp` 는 `internal/core` 만 부른다. 도구 3개
(`casebook_recall` · `casebook_capture` · `casebook_review`)와 `initialize.instructions`
행동 계약, 그리고 **모든 도구 응답에 붙는 편승**이 산출물이다.

**스택:** Go 1.25 · `github.com/modelcontextprotocol/go-sdk` v1.7.0

---

## Global Constraints

이 절은 모든 태스크의 요구사항에 암묵적으로 포함된다.

- **어댑터는 `core` 만 부른다. `core` 는 어댑터를 모른다.** (스펙 §4.1)
  `mcp` 패키지는 `internal/core/*` 만 import 한다. `internal/adapter/cli` 를 import 하지 않는다.
- **stdout 은 JSON-RPC 채널이다.** `cb mcp` 실행 중 stdout 에 한 바이트라도 프로토콜
  아닌 것이 섞이면 세션이 깨진다. 로그·경고는 전부 stderr.
- **건너뛴 노트를 침묵시키지 않는다.** `SkippedNote` 를 stderr 로만 보내면 MCP 경로에서는
  에이전트가 영영 모른다 — stderr 는 호스트 로그로 가고 컨텍스트에 안 들어간다.
  **도구 응답 본문에 넣는다.** ([[casebook-결정-건너뛰기정책-침묵금지-2026-08-07]] 이
  "어댑터마다 다시 처리해야 한다. 빠뜨리면 그 경로에서 침묵이 부활한다"로 예고한 자리다.)
- **편승은 모든 도구에 붙인다.** (스펙 §8) `capture` 는 `core/capture` 가 이미
  `Result.Related` 로 주므로 그대로 쓰고, `review` 는 어댑터가 `search.Recall` 을 부른다.
  `recall` 은 결과 자체가 결정이므로 중복해 붙이지 않는다.
- **도구 이름은 `casebook_` 접두어**로 고정한다 (스펙 §7.1).
- **Go 1.25 floor.** SDK v1.7.0 이 `go >= 1.25` 를 요구해 `go.mod` 의 go 지시자가
  1.23.3 → 1.25.0 으로 올라간다. `GOTOOLCHAIN=auto` 는 Makefile 에 이미 고정돼 있고
  CI 도 1.25 다. **`go install` 안내에 영향이 있으므로 README 를 고쳐야 한다**(Task 5).
- 테스트 볼트는 `internal/testutil` 의 헬퍼로 격리한다. 실볼트를 건드리지 않는다.

## 파일 구조

| 파일 | 책임 |
| --- | --- |
| `internal/adapter/mcp/server.go` | 서버 조립 — `New()` · `Serve()`. 도구 등록 지점. |
| `internal/adapter/mcp/instructions.go` | `initialize.instructions` 본문 생성 |
| `internal/adapter/mcp/tools.go` | 도구 3종의 입출력 타입과 핸들러 |
| `internal/adapter/mcp/render.go` | 응답 본문 렌더링 — 편승 블록 · 건너뜀 경고 |
| `internal/adapter/cli/mcp.go` | `cb mcp` 서브커맨드 (얇은 래퍼) |

## 이 계획에서 하지 않는 것

- **미확인(pending) 건수** — 스펙 §8 의 instructions 는 "미확인 M건"을 포함하지만,
  pending 을 만드는 것은 Plan 3 의 데몬이다. 소스가 없는 값을 지금 0 으로 박아 두면
  거짓말이 된다. **Plan 3 에서 instructions 에 한 문단을 더한다.** 지금은 그 자리를 비운다.
- 리소스·프롬프트 — v1 범위 밖. 도구만 낸다.
- Streamable HTTP 전송 — stdio 만. 원격 호스트는 v2.

**Interfaces:**
- Produces: `mcp.New(c *config.Config, l *store.Layout) *sdk.Server` · `mcp.Serve(ctx, srv) error`
- Produces: `mcp.buildInstructions(l *store.Layout) (string, []store.SkippedNote)`

- [ ] **Step 1: instructions 실패 테스트** — 결정 3건짜리 볼트에서 (a) 건수가 들어가고
      (b) `casebook_recall` 호출 계약 문장이 들어가고 (c) 결정이 0건이면 계약 문장만 남는지.
- [ ] **Step 2: `buildInstructions` 구현.** 최근 결정 덤프가 아니라 **행동 계약**이다
      (스펙 §8). 건너뛴 노트가 있으면 그 사실도 넣는다.
- [ ] **Step 3: 서버 기동 테스트** — `sdk.NewInMemoryTransports()` 로 클라이언트를 붙여
      `initialize` 응답의 `Instructions` 가 비어 있지 않고, `ListTools` 가 3개를 낸다.
- [ ] **Step 4: `New`·`Serve` 구현.** `Serve` 는 `&sdk.StdioTransport{}`.
- [ ] **Step 5: `cb mcp` 서브커맨드.** `loadFrom(cmd)` 로 설정을 읽고 `New`→`Serve`.
- [ ] **Step 6: stdout 오염 테스트** — `cb mcp` 를 실제 프로세스로 띄워 stdout 이
      JSON-RPC 만 담는지 확인한다. (`os/exec` + 초기화 핸드셰이크 1왕복)
