# priorcase 데스크탑 감독 앱 — 설계

> 2026-08-12. 볼트 결정 노트 5건을 하나로 묶은 것이다. 각 항목의 근거는 그쪽에 있다.
>
> **범위는 로컬 앱까지다.** 팀 상태 서버는 별도 스펙으로 뺐다 — 미결이 5건이고
> (인증·호스팅·보고 주기·권한·오프라인) 그것 때문에 로컬 앱 착수가 밀리면 안 된다.
> 앱은 나중에 팀 면을 탭으로 붙일 수 있게 열어 둔다.

## 1. 무엇을 만드는가

**기계가 한 일을 사람이 승인·정정·판정하는 자리.**

사람이 무언가를 적는 곳이 아니다. 이 제품의 원칙이 *"자동으로 기록해 준다"* 이므로,
사람에게 남는 일은 **확인·검증·판정** 셋뿐이고 그 셋은 전부 타이핑이 아니라 클릭이다.

→ [[priorcase-결정-데스크탑앱-감독표면-입력아님-2026-08-12]]

### 왜 필요한가 — 실측

| | 기계가 한 일 | 사람이 해야 할 일 | 지금 |
| --- | --- | --- | --- |
| 확인 큐 | "여기 결정이 있는 것 같다" 표시 | 맞나 확인 | **27건 누적** |
| 검토 큐 | 판별기가 노트를 만듦 | 맞나 검증 | 만든 것 1건, **근거 날조 있었음** |
| 회고 큐 | 결정을 기록 | 결과 판정 | `outcome` 98건 중 판명 **2건 (2%)** |

수명 관리 2% 가 핵심 신호다. `prior review --outcome good` 은 처음부터 있었다 —
안 쓰인 이유는 **되돌아볼 순간을 아무도 만들어 주지 않아서**다. 기록은 훅이 자동으로
시키는데 회고는 시키는 사람이 없다. CLI 는 상주하지 않으므로 구조적으로 못 하는 일이다.

## 2. 형태

**메뉴바 상주 + 조용한 알림.**

- 항상 떠 있다. 아이콘에 **숫자만** 붙는다 (`확인 3 · 회고 2`).
- **푸시 알림을 보내지 않는다.** 먼저 말을 거는 도구는 지워지고, 앱이 지워지면
  자동 기록까지 같이 잃는다.
- 사람이 클릭할 때 보여 준다.

이 프로젝트가 이미 같은 판단을 여러 번 했다 — 팀 이식성 경고는 볼트가 git 일 때만,
색인/git 경고도 그럴 때만 낸다. 소음은 사람에게 경고를 무시하는 법을 가르친다.

## 3. 화면

### 3.1 확인 큐

미확인 구간을 하나씩. 발췌와 시그널을 보여 주고 두 버튼.

```
2026-08-11 · priorcase · 시그널 결정·선택
─────────────────────────────────────────
에이전트: 측정이 하나를 확실히 골라냅니다…
(발췌 6~8줄)

  [결정이다 → 기록한다]     [아니다 → 지운다]
```

- `[아니다]` → `prior pending --resolve <id>` (있음)
- `[결정이다]` → 그 구간을 판별기에 넘긴다. 사람이 본문을 쓰지 않는다(원칙).
  판별기가 노트를 만들면 그 결과가 검토 큐로 넘어간다.

지금 CLI 로는 트랜스크립트 경로+오프셋이라는 긴 ID 를 복사해야 한다.

**한 줄에 보여 줄 것** (2026-08-12 실측에서 나온 것):

| | 왜 |
| --- | --- |
| 날짜 · 도메인 | 어느 프로젝트의 언제 일인가 |
| 시그널 | **없을 수 있다.** 판별기가 있으면 필터를 건너뛴다(D9) — 27건 중 2건이 그랬다 |
| 발췌 크기 | 실측 880B~4.9KB. 한 화면에 안 들어가는 것이 절반이다 |
| **그날 그 도메인에 기록된 결정 수** | "이미 남겼나" 를 가장 빨리 답한다 |

마지막 줄이 실제로 판단을 바꾼다. 큐를 손으로 비워 보니 **"이 구간이 결정인가" 보다
"이 결정이 이미 남았나" 가 훨씬 자주 묻는 질문이었다.** 앞은 판별기가 답하고,
뒤는 사람이 답한다.

> **⚠ 선행 작업**: `[결정이다]` 에 해당하는 명령이 **없다.** 승격은 훅이
> `SessionEnd`·`PreCompact` 에서 큐 전체를 도는 형태뿐이고, 구간 하나를 지목해
> 부를 길이 없다. `prior promote <id>` 같은 것이 필요하다.
>
> 승격 로직 자체는 `daemon.Promote` 에 이미 있고 훅과 데몬이 공유한다
> ([[priorcase-결정-승격은훅과데몬공용-2026-08-09]]). 한 건짜리 진입점만 없다 —
> 쓰기 경로를 또 만들지 말고 그 함수를 재사용해야 한다.

### 3.2 검토 큐 — 가장 중요한 화면

판별기가 만든 노트를 **발췌와 나란히** 놓는다.

```
발췌 (판별기가 본 것)          │  판별기가 쓴 노트
──────────────────────────────┼──────────────────────────
사용자: canonlog 로 가자        │  ## 근거
에이전트: 확인했습니다…         │  canonlog 는 판례집의
                              │  라틴어 표현으로 …   ← 대화에 없다

  [맞다]   [고친다]   [지운다]
```

**이 화면이 앱의 존재 이유에 가장 가깝다.** ③ 자동 승격이 만든 유일한 노트에
근거 날조가 있었고(없는 어원을 지어냄), 그것을 사람이 우연히 발견했다. 지시문에
제약을 넣었지만 **그건 완화이지 보장이 아니다** — 판별기는 LLM 이다.

`[고친다]` 는 예외적으로 텍스트를 다룬다. 원칙("사람이 적지 않는다")과 충돌하지
않는다 — 새로 쓰는 것이 아니라 **틀린 것을 고치는** 일이다.

> **⚠ 선행 작업**: 지금 구조로는 이 화면이 **불가능하다.** 승격과 동시에
> `ResolvePending` 이 구간을 지우고, 원장(`promotions.jsonl`)에는 발췌가 없다.
> 검토 큐가 노트만 있고 **대조할 발췌가 없다.**
>
> 2026-08-12 에 21건을 승격시키고 만들어진 노트를 검증하려다 실제로 막혔다.
> 상세와 대안은 [[priorcase-결정-승격발췌-원장에남긴다-2026-08-12]].

**실측으로 확인한 것 하나** — 판별기가 근거를 지어내지 않는다. 그 노트의
`## 고려한 대안` 이 "발췌에 명시되지 않았습니다" 였다. 지시문의 날조 금지 제약이
눈에 보이게 일하고 있다. 다만 **완화이지 보장이 아니다** — 그래서 이 화면이 있다.

### 3.3 회고 큐

```
2026-08-09 · 재회수 4회
"casebook 을 팀의 AI 가 공유하는 결정 베이스로 포지셔닝한다 — …"
                                          — zesty <…>

  [좋았다]   [나빴다]   [아직]
```

방아쇠: **재회수 2회 이상 `OR` superseded**, 그리고 `outcome: pending` 인 것만.
최소 경과 기간 없음.

→ [[priorcase-결정-회고방아쇠-재회수2회-기간없음-2026-08-12]]

**`[아직]` 을 고른 뒤 언제 다시 묻는가** — 같은 방아쇠가 **한 번 더** 울릴 때까지
안 묻는다. 즉 재회수 카운트가 현재값+1 이 될 때. 시간을 쓰지 않는 이유는 회고
방아쇠와 같다: 규칙이 둘이 되면 "왜 안 뜨지" 를 설명할 수 없다.

### 3.4 상태

`prior doctor` 가 내는 검사 10개를 그대로. 큐가 셋 다 비었을 때 앱이 보여 줄 것이
이것뿐이므로 **비어 있어도 반드시 채운다.**

배선이 안 됐으면 여기서 `prior init --apply` 를 대신 실행한다. 지금 새 팀원의 첫
마찰이 그것이다.

## 4. 아키텍처

```
┌─ Tauri 2 앱 ────────────────┐
│  UI (웹뷰)                   │
│  Rust 측: 프로세스 실행       │
└──────────┬──────────────────┘
           │ prior queue --json      (읽기, 폴링)
           │ prior pending --resolve │
           │ prior review --outcome  │ (쓰기)
           │ prior init --apply      │
           ▼
      prior (Go 단일 바이너리)
           ▼
      볼트 (마크다운) · ~/.local/state/priorcase
```

**앱은 파일을 직접 다루지 않는다.** frontmatter 방출·스키마 검증·색인 갱신이 두
벌이 되면 한쪽만 고쳐진 채로 남는다 — 이 프로젝트가 감사에서 죄목으로 든 것이
정확히 그것이고 arch 테스트로 막아 둔 것도 그것이다. 앱은 **또 하나의 어댑터**다.

### 4.1 읽기 — `prior queue --json`

이미 있다(2026-08-12 구현). 세 큐와 상태를 **한 스냅샷**으로 준다.

```json
{
  "confirm": [{"id","domain","when","signals","excerpt"}],
  "review":  [{"id","domain","at","path"}],
  "retro":   [{"stem","date","domain","summary","author","reason","hits"}],
  "health":  [{"name","level","detail","fix"}],
  "warnings": ["…"]
}
```

- 네 번 따로 부르면 그 사이에 훅이 돌아 **서로 어긋난 큐**가 나란히 보인다.
- `level` 은 `ok|warn|fail|unknown` 문자열이다. 정수면 앱이 `0 == 정상` 을 외워야
  하고 상수 순서가 바뀔 때 **조용히 뒤집힌다.**
- 빈 큐는 `[]` 다. `null` 이면 앱에서 "아직 안 왔다" 와 "할 일이 없다" 가 구별되지 않는다.
- `warnings` 는 없으면 **키 자체가 빠진다.** 있으면 큐가 불완전하다는 뜻이다.

계약은 `internal/adapter/cli/queue_test.go` 가 못 박는다.

### 4.2 갱신 주기

**폴링.** 앱이 뜰 때, 창을 열 때, 그리고 30초마다.

`prior queue --json` 이 실측 1.0초다(결정 98건). 회고 큐는 매번 계산하고 캐시하지
않는다 — 상태를 하나 더 두면 볼트를 손으로 고쳤을 때 틀어진다.

파일 감시(fsnotify)를 쓰지 않는 이유: 볼트와 상태 디렉토리 양쪽을 봐야 하고,
그래도 회고 큐는 재계산해야 한다. 얻는 것이 적다.

**1.0초는 결정 98건 기준이다.** 볼트가 10배가 되면 재회수 계산이 O(n²) 로 는다
(각 노트마다 전체 회수). 그때는 측정하고 캐시를 다시 본다.

### 4.3 쓰기

전부 `prior` 명령이다. 실패하면 **조용히 넘어가지 않는다** — 큐에서 사라졌는데
볼트에 반영이 안 되면 사람은 답한 줄 안다.

## 5. 오류 처리

| 상황 | 앱의 동작 |
| --- | --- |
| `prior` 를 못 찾음 | 설치 안내 화면. 큐 대신 그것만 보여 준다 |
| `prior queue` 가 0 아닌 종료 | stderr 를 그대로 보여 준다. 빈 큐로 그리지 않는다 |
| `warnings` 가 비어 있지 않음 | 큐 위에 배너. **"할 일 없음" 으로 그리면 안 된다** |
| 쓰기 명령 실패 | 그 줄을 큐에 되돌리고 이유를 보여 준다 |
| 볼트가 없거나 설정이 깨짐 | `health` 의 `fail` 항목을 크게. 큐는 비운다 |

**빈 큐와 실패를 구별하는 것이 이 표의 전부다.** 이 시스템은 모든 부품이 실패해도
대화를 막지 않도록 설계됐고, 그 대가로 고장이 정상과 구별되지 않는다. 앱이 그 구별을
못 하면 앱도 같은 병에 걸린다.

## 6. 테스트

- **계약**: `queue_test.go` 가 이미 키 목록을 고정한다. 앱은 그 형태만 신뢰한다.
- **앱 쪽**: `prior` 를 가짜 스크립트로 바꿔 각 오류 상황을 재현한다
  (없음·0 아닌 종료·깨진 JSON·warnings 있음). 표 5행이 그대로 테스트 5개다.
- **수동**: 큐가 셋 다 빈 상태와 셋 다 찬 상태를 눈으로 본다. 빈 상태가 "고장난
  것처럼" 보이지 않아야 한다.

## 7. 배포

`.app` 배포는 **애플 공증을 되살린다** — npm 경로가 없앤 비용이다.
그리고 `tauri build` 의 **DMG 번들링이 비대화형 세션에서 멈춘다**(omni 실측).
`.app` 까지는 된다. CI 에서는 `.app` 만 만들고 DMG 는 별도로 다룬다.

→ [[omni-결정-Tauri빌드-DMG헤드리스제약-2026-08-01]]
→ [[priorcase-결정-배포경로-npm우선-2026-08-09]]

**CLI + 훅을 대체하지 않는다.** 앱은 그것을 감싼다 — 둘 중 하나를 고르는 것이 아니다.

## 8. 범위 밖

- **빠른 기록(수동 입력)** — 원칙에 어긋난다. 사람에게 적으라고 하는 순간 다른
  메모 앱과 같아진다.
- **볼트 브라우저(검색·타임라인)** — Obsidian 이 이미 하고, 회수는 CLI·에이전트가
  이미 한다. 실측된 구멍을 하나도 안 메운다.
- **팀 상태 서버** — 별도 스펙. 앱은 탭 자리만 열어 둔다.
- **화면 녹화·음성** — 보류. 호스트 파서를 붙이고 남은 구멍을 잰 뒤에 판단한다.

## 9. 선행 작업

앱을 짜기 전에 CLI 쪽에 하나가 있어야 한다.

- ~~**`prior promote <id>`**~~ — ✅ 2026-08-12 구현.
- **승격 발췌를 원장에 남기기** — 검토 큐(§3.2)가 노트를 발췌와 대조하려면 필요하다.
  지금은 승격과 동시에 사라진다. `TrimLedgerText` 로 잘라 `promotions.jsonl` 에 싣는다.

이미 있는 것: `prior queue --json` · `prior promote` · `prior review --summary` ·
`prior pending --resolve` · `prior init --apply` (전부 2026-08-12 기준).

## 10. 미결

이 스펙 범위 안에서는 없다. 팀 서버의 미결 5건(인증·호스팅·보고 주기·권한·오프라인)은
그쪽 스펙으로 넘겼다.
