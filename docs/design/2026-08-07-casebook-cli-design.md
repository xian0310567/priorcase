# casebook 설계 스펙

- **날짜**: 2026-08-07
- **상태**: 승인 대기
- **대상**: `~/project/casebook` — 오픈소스 CLI `cb`
- **전제 문서**: `readme.md` (작업 지시서 Phase 0~9), 2026-08-04 실측 감사

---

## 1. 문제 정의

지금 운영 중인 세컨드브레인은 Claude Code 훅 5개 + 셸 스크립트 11개(~1,830줄)로 되어 있다.
2026-08-04 감사에서 확정된 문제는 셋이다.

1. **능동 진입점이 없다.** capture·recall·review 로직은 전부 존재하지만 각각
   LLM+transcript 전용 / 훅 파일 내부 / LLM JSON 전용으로 갇혀 있어, 사람이나 에이전트가
   부를 방법이 없다. 그래서 기록의 주 경로가 "훅이 LLM 으로 추측"이 되어 있다.
2. **Claude Code 에 결합돼 있다.** 훅 이벤트명, transcript JSONL 스키마, `claude -p` 호출.
   다른 에이전트에서 쓸 수 없다.
3. **셸이라 조용히 데이터를 잃는다.** `jq` 슬러프 파싱 실패가 구간을 삼키고 체크포인트를
   전진시킨다. 동시 실행 락이 없다. `cut -c` 로케일 함정이 리눅스에서 한글 파일명을 깨뜨린다.
   `/usr/bin/jq` 절대경로 하나가 없으면 전 훅이 무동작한다.

casebook 은 이 셋을 동시에 푼다.

## 2. 이 시스템의 고유 주장

"에이전트가 내린 결정을 사람이 시키지 않아도 남기고, 다음 판단 시점에 알아서 꺼내 주는 층."

메모 앱·RAG·수기 CLAUDE.md 관리와 다른 점은 셋이다.

1. **사전 필터 체인** — 판별을 마지막 단계로 미룬다. 체크포인트 증분 → 턴 수 → 키워드
   시그널을 통과한 소수만 판단 대상이 된다.
2. **2층 구조** — 시간순 원장(`99-작업-로그`)과 회수 대상 정본(`decisions/`)을 분리한다.
   회상에 꺼내 쓰는 건 "한 일"이 아니라 "결정과 교훈"이다.
3. **회수가 자동이다** — 사용자가 검색하지 않는다.

## 3. 결정 요약

| # | 결정 | 근거 요약 |
|---|---|---|

| D6 | **저장 포맷 유지 (마크다운 + frontmatter)** | 기존 42건이 그대로 읽힌다. Obsidian 호환, 사람이 읽고 고칠 수 있다 |
| D7 | **개발은 별도 테스트 볼트** | 구·신 시스템이 같은 볼트에 쓰면 결정이 중복 생성된다 |

## 4. 아키텍처

### 4.1 코어/어댑터 경계

**규칙: 어댑터는 `core` 만 부른다. `core` 는 어댑터를 모른다.**

감사에서 나온 *"쓰기 경로가 둘로 갈라져 스키마 검증이 한쪽에만 있다"* 와
*"frontmatter 방출기가 두 벌"* 이 구조적으로 불가능해진다.

```
casebook/
├── cmd/cb/                    단일 바이너리, 서브커맨드 디스패처
├── internal/
│   ├── core/                  ← 어댑터가 부르는 유일한 API
│   │   ├── config/              설정 단일 정본
│   │   ├── store/               볼트 I/O — 노트 읽기·쓰기, frontmatter, 파일명
│   │   ├── schema/              검증 (접두어 = domain 첫 값, 허용값, 날짜)
│   │   ├── search/              회수. 인터페이스 분리 → 임베딩 교체 가능
│   │   ├── capture/             결정 생성·갱신 (review 포함)
│   │   ├── index/               색인 재생성
│   │   └── rollup/              작업 로그 요약 (v2)
│   ├── adapter/
│   │   ├── cli/                 사람·스크립트·셸 되는 에이전트
│   │   ├── mcp/                 MCP 서버 (도구 + instructions + 편승)
│   │   └── hook/                Claude Code 훅 래퍼 — 입력 파싱 + core 호출만
│   ├── transcript/            호스트별 파서. 인터페이스: (파일) → []Turn
│   │   └── claudecode/          JSONL
│   └── daemon/                fsnotify + 필터 체인 + 플래그
└── testdata/                  골든 파일 (실볼트 42건 사본 포함)
```

`capture` 안에 `review`(outcome·회고·supersedes 갱신)를 넣는다. 둘 다 "결정 노트를 쓰는"
같은 일이고, 지금 분리돼 있어서 로직이 이원화됐다. CLI 로는 `cb capture` / `cb review` 로
갈라 보이되 내부는 한 패키지다.

### 4.2 서브커맨드

| 명령 | 하는 일 |
|---|---|
| `cb capture` | 결정 생성 (스키마 검증 → 쓰기 → 색인 갱신 → 관련 결정 반환) |
| `cb recall <query>` | 결정 검색. `--format inject` 로 훅 주입용 출력 |
| `cb review` | 기존 결정의 `outcome`·회고·`supersedes` 갱신 |
| `cb index` | 색인 재생성 |
| `cb watch` | 데몬 (단일 인스턴스) |
| `cb mcp` | MCP 서버 (stdio) |
| `cb hook <event>` | Claude Code 훅 래퍼. `<event>` = `session-start` \| `user-prompt-submit` \| `stop` \| `pre-compact` \| `session-end` |
| `cb init` | 설정 생성, 훅 배선, 데몬 등록. `--revert` 로 되돌림 |
| `cb rollup` | 작업 로그 주간 요약 (v2) |

## 5. 설정

감사 결과: 개인 설정이 11개 파일 중 7개에 퍼져 있고 볼트 경로 하나만 상수화돼 있었다.
**코드의 개인 설정 리터럴을 0으로 만든다.**

```toml
# ~/.config/casebook/config.toml   (XDG. CASEBOOK_CONFIG 로 오버라이드)
vault = "~/Documents/Obsidian Vault"

[naming]
decision_file = "{domain}-결정-{slug}-{date}.md"
decisions_dir = "{project}/decisions"
worklog       = "99-{project}-작업-로그.md"
index         = "_meta/00-결정-색인.md"

[[domain]]
prefix = "omni"; folder = "omni"; paths = ["~/project/omni"]
[[domain]]
prefix = "occ";  folder = "OCC";  paths = ["~/Documents/automation-dropshipping"]

exclude = ["~/project/NOI"]

[capture]
signals = ["결정", "선택", "하기로", "채택", "대신", "전략", "포기", "변경"]
min_turns = 6
quiesce_seconds = 3
```

- **`CASEBOOK_VAULT` 가 볼트 경로를 덮어쓴다.** 개발 중 테스트 볼트 격리가 이 한 줄.
- 도메인·제외·키워드·파일명 규약이 전부 설정. 새 프로젝트 추가가 "코드 3곳 수정"에서
  "설정 4줄 추가"로 바뀌고, **한 곳만 빠뜨려 조용히 실패하는 함정**이 사라진다.
- **도메인과 제외가 다른 축이다.** 지금 실볼트에서 NOI 가 도메인 목록에 있어 쓰기 경로가
  생기는 회귀가 났는데, 이 구조에서는 그 상태가 표현 불가능하다.
- 국제화가 여기서 열린다. `-결정-` 이 템플릿이므로 영어권은
  `{domain}-decision-{slug}-{date}.md` 를 쓴다.
- 상태 파일(체크포인트·pending·락)은 볼트 밖 `~/.local/state/casebook/`. 볼트에는 문서만.

## 6. 저장 포맷 — 변경 없음

마크다운 + frontmatter 10키(`type` `date` `domain` `summary` `status` `outcome`
`supersedes` `related` `tags` `source_session`)를 그대로 쓴다.

1. 기존 42건이 그대로 읽힌다 → 컷오버에 데이터 마이그레이션이 없다
2. Obsidian 에서 계속 보인다 — 볼트가 casebook 전용 DB 가 되면 도구를 바꾼 게 아니라 잃은 것
3. 사람이 읽고 손으로 고칠 수 있다 (오픈소스 신뢰 요소)
4. Git 으로 버전 관리·diff 가 된다

바뀌는 건 읽고 쓰는 **코드뿐**이다. awk 로 frontmatter 를 파싱하고 `LC_ALL=C sort` 로
우회하던 자리가 YAML 파서와 `[]rune` 으로 바뀌면, 한글 로케일 함정 세 종류(awk 멀티바이트
오판 · sort 유실 · `cut -c` 바이트 절단)가 **표현 자체가 불가능**해진다.

## 7. 기록

### 7.1 에이전트 주도 (주 경로, 실시간)

```
cb capture --domain omni --slug 저장엔진-OPFS --summary "..." [--body -]
casebook_capture(domain, slug, summary, body, supersedes?)
```

둘 다 `core/capture` 하나를 부른다. 스키마 검증을 통과 못 하면 **거부**한다.
응답에 관련 과거 결정을 첨부한다(§8 편승).

결정을 내린 에이전트가 그 자리에서 부르므로 지연이 0이고, 판별 LLM 이 필요 없으며,
근거·대안까지 정확하다. readme Phase 4-A 가 원래 명세한 구조다.

### 7.2 데몬 (안전망, 준실시간)

```
cb watch   단일 인스턴스(락파일) · fsnotify
           → 체크포인트 이후 구간
           → 쓰기가 quiesce_seconds 동안 멎을 때까지 대기
           → 턴 수 임계 (tool_result 레코드는 세지 않음)
           → 키워드 시그널
           → pending 레코드 기록 (LLM 호출 없음)
```

pending 은 다음 세션의 `instructions` 에 "미확인 N건"으로 노출되고, 에이전트가 읽고
판단해 `cb capture` 를 부른다.

**체크포인트 규칙 (단일): 구간을 끝까지 성공 처리했을 때만 전진한다.**
파싱 실패한 줄은 건너뛰되 전진하지 않는다. 감사 결함 1(빈 발췌를 "내용 없음"으로 오판하고
전진)과 2(update 실패만 전진)가 이 한 규칙으로 함께 닫힌다. 소유자가 하나뿐이므로 락 경합
자체가 없다(결함 3).

## 8. 회수

| 겹 | 시점 | 수단 |
|---|---|---|
| 행동 계약 + 최근 N건 + 미확인 M건 | 세션 진입 | `initialize.instructions` |
| 명시 호출 | 주제 전환 | `cb recall` / `casebook_recall` |
| **편승** | casebook 을 쓸 때마다 | 모든 도구 응답에 관련 결정 첨부 |
| 강제 주입 | 매 프롬프트 | Claude Code 훅 |

**편승이 세션 내 커버리지의 핵심이다.** 도구 결과는 그 자체로 컨텍스트 주입이므로,
casebook 도구를 무엇을 부르든 응답에 관련 결정을 얹는다. 특히 `capture` 시점은 곧
결정 시점이므로 그때 과거 결정이 따라 나오는 것이 가장 정확한 타이밍이다.

`initialize.instructions` 는 최근 결정 덤프가 아니라 **행동 계약**을 심는다:

> 이 워크스페이스에는 과거 결정 N건이 있다. 새 작업이나 주제로 넘어갈 때마다
> `casebook_recall(주제)` 을 먼저 호출하라. 호출하지 않으면 이미 뒤집힌 결정을
> 다시 제안하게 된다. 미확인 구간 M건이 있다.

## 9. 호스트별 보장 수준

| | Claude Code | MCP 전용 호스트 |
|---|---|---|
| 결정 순간 기록 | 에이전트 `cb capture` | 동일 |
| 놓친 기록 줍기 | 데몬 | 동일 |
| 세션 진입 컨텍스트 | 훅 (보장) | `instructions` (사실상 동등) |
| **주제 전환 시 회수** | **훅 (강제)** | **계약 + 편승 (유도)** |

굵은 칸 하나가 유일한 차이다. 이 표를 README 에 그대로 싣는다 — 과장하지 않는다.

**호스트별 transcript 파서는 필요하다.** 다만 읽기 전용이고 인터페이스가
`(파일) → []Turn` 하나로 좁으며, 하나가 깨져도 다른 호스트에 영향이 없다. 훅 어댑터처럼
이벤트 모델·수명주기·에러 규약을 호스트마다 다시 맞출 필요는 없다.

## 10. v1 범위

**포함** — `core` 전부 · CLI 8개 서브커맨드 · MCP 서버 · Claude Code 훅 래퍼 +
JSONL 파서 · 데몬

**제외 (v2)** — 다른 호스트 파서 · `rollup`(기존 `rollup.sh` 로 버팀) · 임베딩 검색 ·
자정 작용(주제 전환 감지)

자정 작용을 뺀 이유: "주제가 바뀌었다"를 규칙으로 판정하기 어렵고 오탐이 나면 오히려
방해가 된다. v1 은 계약+편승으로 가고, 실사용 커버리지가 부족하면 그때 데이터를 보고
규칙을 만든다.

`rollup.sh` 는 훅이 아니라 수동 실행 스크립트이므로 §12 의 훅 제거 대상이 아니다.
`cb rollup` 이 나올 때까지 그대로 둔다.

## 11. 테스트

셸에서 못 쓰던 테스트가 이 프로젝트의 핵심 산출물이다. **감사 결함 하나당 테스트 하나**.

| 테스트 | 고정하는 결함 |
|---|---|
| 마지막 줄이 잘린 JSONL → 앞 구간 처리, 체크포인트 **미전진** | 결함 1 (구간 삼킴) |
| 대상 없는 update → 체크포인트 미전진 | 결함 2 |
| 동시 `cb watch` 2개 → 두 번째는 락에서 즉시 종료 | 결함 3 |
| 유사 slug 중복 생성 시도 → 거부 | 결함 4 |
| 140자 한글 slug 절단 → 깨진 UTF-8 없음 (rune 기준) | `cut -c` 로케일 함정 |
| NFD 파일명 입력 → NFC 정규화 후 매칭 | tar 복원 함정 |
| `../CLAUDE` 등 경로 순회 → 거부 | 감사에서 도달 가능 확인 |
| frontmatter 라운드트립: 읽고 다시 쓰면 바이트 동일 | 방출기 이원화 |
| 접두어 ≠ domain 첫 값 → 거부 | 스키마 강제 |

`testdata/` 에 실볼트 42건의 사본을 골든으로 넣는다. 파서·검증·색인이 실데이터에서
깨지지 않는 것을 CI 가 매번 확인한다.

## 12. 컷오버

```
1. 개발      CASEBOOK_VAULT=~/casebook-test        기존 훅 그대로 가동
2. 병행검증  실볼트를 읽기만 — cb recall 결과를 기존 훅 주입과 비교
3. 게이트    아래 조건 전부 통과
4. 전환      cb init → 기존 훅 5개 제거 + casebook 배선 + 데몬 등록
             cb init --revert 로 원복
```

**게이트 조건**

- [ ] 실볼트 42건을 `cb index` 가 손실·왜곡 없이 재생성
- [ ] `cb recall` 상위 3건이 기존 훅 결과와 실질 동등
- [ ] 결정 순간 `cb capture` → 규약 파일명·스키마로 생성
- [ ] 데몬이 놓친 결정을 pending 으로 잡고, 다음 세션 `instructions` 에 노출
- [ ] Obsidian 을 완전히 종료한 상태에서 위 전부 재확인 (앱 독립성)
- [ ] Claude Code 가 아닌 MCP 호스트 하나에서 도구 호출·편승 확인

기존 훅 5개는 3단계까지 손대지 않는다. 삭제는 4단계에서 한 번에.

## 14. 채택하지 않은 대안

| 대안 | 기각 사유 |
|---|---|
| POSIX sh 유지 + 정리 | 감사 결함 대부분이 셸 고유(로케일·BSD/GNU·jq 의존). 테스트를 쓸 수 없어 데이터 소실 회귀를 못 막는다 |
| Python / TypeScript | 런타임 의존이 MCP 서버 기동 실패의 최대 원인. `/usr/bin/jq` 와 같은 실패 계열 |
| MCP 만 만들고 훅 폐기 | MCP 에 서버→대화 push 채널이 없다. 자동 회수라는 고유 주장을 포기하는 것 |
| 호스트별 훅 어댑터 전면 구현 | 유지보수가 호스트 수에 비례하고, 훅이 없는 호스트는 애초에 불가능 |
| MCP sampling 으로 판별 | 2026-07-28 스펙에서 deprecated. "신규 구현은 채택하지 말 것" |
| 데몬이 자체 API 키로 판별 | 키 등록이 오픈소스 진입 장벽. 에이전트에게 넘기면 무료이고 맥락이 더 풍부하다 |
| 같은 볼트에서 구·신 병행 | 결정이 중복 생성된다 |

## 15. 미해결 항목

- **데몬 수명주기 등록 방식** — launchd(macOS) / systemd(Linux) / MCP 서버가 자동 기동.
  `cb init` 이 무엇을 하는지 구현 단계에서 확정한다.
- **회수 점수 함수** — 현재 훅의 가중치를 그대로 옮길지, 골든 세트를 만들어 재조정할지.
  §12 게이트의 "실질 동등" 판정 기준과 함께 정한다.
- **`instructions` 미지원 호스트** — 무시하는 클라이언트가 있을 경우의 대체 경로.
  실측 후 판단.
